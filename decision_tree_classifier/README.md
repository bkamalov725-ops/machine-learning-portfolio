# Hidden Pairs: decision trees, ensembles and SVM

Учебная лабораторная и командное решение соревнования по бинарной классификации анонимных числовых данных. Каждая строка описывает пару скрытых наблюдений: `target = 1` означает одну скрытую сущность, `target = 0` — разные.

**Итоговая выбранная модель: RBF-SVM, validation ROC-AUC ≈ 0.947921.** Это оценка на предоставленной validation-выборке, не accuracy и не результат публичного или приватного leaderboard.

Командный SVM-notebook: **Chess Monsters — Ермолаев, Камалов, Байрамов**. Исходное имя: `svm_dense_search_Ермолаев_Камалов_Байрамов_chess_monsters.ipynb`.

## Данные и оценка

- Train: 2 520 объектов; validation: 560; test: 1 116.
- 512 числовых признаков. `row_id` и `target` не используются как признаки.
- Все модели обучаются только на train. Для сравнения используется предоставленная validation-выборка, разделённая по скрытым сущностям.
- Метрика ROC-AUC оценивает ранжирование положительных примеров выше отрицательных, а не долю правильных ответов при пороге 0.5.
- Submission содержит только `row_id` и вероятность `target = 1`, с исходным порядком строк и без дополнительного индекса.

Ниже — результаты проверочного запуска 1 октября 2026 года, scikit-learn 1.8.0. Время зависит от компьютера. Общий seed: `20260916`. Везде используются исходные 512 признаков.

В прежнем сохранённом выводе Random Forest имел ROC-AUC 0.885497; повторный запуск дал 0.884490. Исторический результат не выдаётся за воспроизведённый; точная причина расхождения не исследовалась. Результат выбранного SVM воспроизведён до шести знаков.

SVM заметно улучшил результат основных моделей лабораторной. Однако он не является безусловным максимумом среди всех локальных проб: отдельные смеси SVM и MLP давали примерно 0.9487 на той же validation. Здесь опубликована выбранная командой SVM-конфигурация, а не утверждение о превосходстве на неизвестном private test.

## Как устроено итоговое решение

1. Полный поиск сравнивает RBF-SVM на исходных признаках, после StandardScaler, RobustScaler и двух вариантов PCA, а также SVM с полиномиальным ядром степени 2. Преобразования находятся внутри Pipeline и обучаются заново в каждом CV-fold.
2. Широкая сетка оценивается через трёхкратную StratifiedKFold на train. Для трёх лучших RBF-веток выполняется уточняющий поиск.
3. Кандидаты сравниваются через 5-fold CV с двумя повторениями на train (`random_state=SEED+101`). Исходная конфигурация `C=2.5`, `gamma=0.007` совпала с победителем поиска: средний CV ROC-AUC ≈ 0.928433.
4. Выбранный SVM использует все исходные признаки **без масштабирования и PCA**. RBF-ядро позволяет строить нелинейную границу решения.
5. `CalibratedClassifierCV(method="sigmoid", ensemble=False)` обучает преобразование оценок SVM в вероятности по out-of-fold прогнозам пяти folds train. Финальный SVM обучается на всём train; validation в калибровку не входит.
6. После оценки на validation создаются непрерывные вероятности для test и проверяется формат CSV.

Случайная CV внутри train не воспроизводит разделение по скрытым сущностям, поэтому её оценки не заменяют предоставленную validation. Многократное сравнение вариантов на одной validation также может привести к подгонке выбора модели под неё. Независимый итоговый результат соревнования здесь не заявляется.

## Запуск

Использован Python 3.14.3. Скачайте разрешённые вам файлы соревнования и положите в эту папку:

```text
train.csv
validation.csv
test.csv
sample_submission.csv
```

Из корня репозитория:

```bash
cd decision_tree_classifier
python -m pip install -r requirements.txt
python -m jupyter lab
```

Откройте нужный notebook и выполните **Restart Kernel → Run All**:

- Основная лабораторная: `baseline_student-ru.ipynb`; результат — `runs/submission_tree.csv`.
- Выбранный SVM без повторного подбора: `svm_reproduce-ru.ipynb`; результат — `runs/final-<дата-время>/submission_svm.csv`.
- Полный поиск: `svm_final-ru.ipynb`; таблицы, модели и submission сохраняются в `runs/<дата-время>/`. Этот вариант требует существенно больше времени и дискового пространства.

Папка `runs/` не публикуется в Git. Не запускайте notebooks одновременно в одну секунду: выходные каталоги разделены временными метками.

## Подготовка к публикации и воспроизводимость

В лабораторной исправлена только ошибочная проверка уникальности идентификаторов (`is_unique` вместо `unique()` в assert), а выходной CSV перенесён в `runs/`. В полном SVM-notebook абсолютный путь чужого компьютера заменён относительным, результаты перенесены в `runs/`, старые выводы ячеек очищены: они содержали пути и временные метки разных запусков. Логика поиска сохранена.

Короткий SVM-notebook добавлен для воспроизведения выбранных параметров. Версия scikit-learn в сохранённом командном запуске — 1.9.0; зависимости здесь фиксируют доступное проверочное окружение 1.8.0. Полный поиск заново при публикации не выполнялся; одинаковый победитель поиска между версиями не гарантируется. Основная лабораторная и короткий SVM проверяются полным последовательным запуском; их сохранённые выводы показывают результаты этого запуска.
